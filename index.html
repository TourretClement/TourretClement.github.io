SAE 23 : Mettre en place une solution informatique pour l'entreprise

Contexte : Ce projet se réalise en autonomie à l’université durant plusieurs travaux pratiques et dirigés.

Objectif : Mettre en place un outil de support pour le service informatique de l’université. Créer un site web de gestion de tickets de support. Le site devrait contenir des informations disponibles pour tous les utilisateurs du système. Un utilisateur peut créer un ticket de support, suivre l’avancement de ses tickets de support, et supprimer un ticket de support via une base de données.

Travail réalisé : Nous disposons de deux dossiers, un frontend et un backend. Le frontend, qui nous a été fourni, correspond à la structure de la page web, donc aucune interaction n’est possible avec celui-ci. Pour ce faire, nous devons coder dans le dossier backend, c’est-à-dire que les informations qui seront exécutées dans ce dossier ne seront pas visibles par l’utilisateur du site. Dans un premier temps, nous devons comprendre le code donné pour pouvoir le structurer dans notre dossier backend. Une fois la base du dossier backend réalisée, nous devons ensuite créer une base de données sous le logiciel MongoDB. Pour ce faire, nous avons besoin, sous Windows, de MongoDB Atlas, qui est un superviseur de base de données, et de MongoDB Compass, qui nous permettra d’accéder à notre base de données.

Résultat : Le travail que j'ai réalisé est fonctionnel.

SAE 53 : Sécurisation avancée et supervision d’un système d’information

Contexte : Ce projet a été réalisé au semestre 5 du BUT en groupe de 3 personnes.

Objectif : Dans le cadre de la SAE5.Cyber.03, l’objectif est de concevoir une maquette représentative d’une problématique de sécurité informatique, d’y exécuter un scénario d’attaque réaliste, de démontrer sa détection à l’aide d’outils de supervision, puis de mettre en place des mesures de sécurisation permettant de limiter ou bloquer cette attaque.

Travail réalisé : Au cours de ce projet, j'ai conçu, sécurisé et audité une infrastructure serveur sous Linux (Debian). J'ai d'abord renforcé la sécurité du système (hardening) en configurant une authentification forte sur SSH (2FA avec modules PAM) et en corrigeant les permissions critiques pour prévenir les escalades de privilèges. Pour la supervision (Blue Team), j'ai déployé des agents Splunk afin de centraliser l'analyse des logs et de tracer les incidents, tout en mettant en place l'EDR Velociraptor pour isoler et mettre en quarantaine les machines compromises via des règles de pare-feu (UFW/iptables). Enfin, j'ai adopté une approche offensive (Red Team) en utilisant Metasploit et Python pour auditer la surface d'attaque, tester la robustesse des configurations et simuler des compromissions locales (tâches Cron).

Résultats : Notre scénario d'attaque était complexe et nos mesures de défense utilisées ont satisfait notre professeur.
